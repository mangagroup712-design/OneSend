# OneSend 同一ネットワーク ファイル転送

同じネットワーク上で待機しているブラウザー同士が、受信側の承認後にファイルを直接送るサービスです。ファイル本体は WebRTC DataChannel で端末間を流れ、サーバーに保存されません。

## ページ

- `/` - サービス案内
- `/client.html` - ファイル選択・貼り付け、端末選択、テキスト／URL共有、送信進捗、折り畳み式の速度改善ヒント
- `/read.html` - 端末名・任意のPIN設定、全画面の受信承認、正確な受信進捗、プレビュー、テキスト履歴、ZIP一括ダウンロード

## 使い方

1. 受信側で `/read.html` を開き、端末名を設定します。必要ならPINを有効にします。
2. 送信側で `/client.html` を開いてファイルを選ぶか貼り付け、受信端末を選び「送信」ボタンを押します。
3. 受信側で送信元、ファイル名、容量、件数を確認し、「受け取る」か「拒否」を選びます。要求は30秒でタイムアウトします。PIN設定中は送信側に入力欄が表示されます。
4. 承認後にファイル本体をブラウザー間で直接転送します。進捗は受信確認された実バイト数を反映します。

ページにフォーカスがあるとき画像やファイルを Ctrl+V / Cmd+V で追加できます。テキストやURLは共有欄へ貼り付け、端末を選んで送信します。受信テキストの履歴は受信画面のメモリ上だけに保持されます。

## ローカル / LAN で動かす

```bash
npm start
```

起動ログに表示された `LAN access` の URL を同じネットワークの別端末で開きます（初期ポートは8080）。Node.js版では接続元のローカルサブネットごとに端末一覧を分けます。8080番が使用中の場合は、別のポートを指定できます。

```powershell
$env:PORT=8081; npm start
```

macOS / Linux の場合は `PORT=8081 npm start` を使います。接続の合図（シグナリング）だけこのサーバーが扱い、ファイルはブラウザ間で直接送られます。LAN内の端末から開く場合も、送信側と受信側で同じURL・ポートを使ってください。

PWAのインストールとAndroid Chromeの共有メニュー連携にはHTTPSが必要です。

## Cloudflare へのデプロイ

静的配信だけだとシグナリング API が無いため、`worker.js` を Workers（Assets + Durable Objects）としてデプロイしてください。`wrangler.toml` に転送部屋と端末ディレクトリを設定しています。

Framework presetは `None`、ビルドコマンドは不要です。

## 転送の仕組みと速度

送信側は相手ブラウザーのSCTPメッセージ上限に合わせて最大512KB単位で読み、DataChannelのバッファを監視しながら送ります。進捗・速度は実際のバイト数から計算します。複数ファイルは選択順に連続転送します。1ファイルの容量上限は2GBです。

転送を速くするには、有線LANを使う、Wi-Fiルーターの近くで5GHz／6GHz帯を使う、他の大容量通信・VPN・ゲストWi-Fiを避ける、省電力モードを解除して画面を前面に保つ方法があります。遅い状態が続く場合は、端末・ブラウザー、Wi-Fi帯域、表示速度、ファイル数と容量をもとに追加の改善を検討してください。

ブラウザーはOSの端末名やLAN上の全端末を直接読み取れません。OneSendの受信画面を開いて待機中の端末を一覧にし、表示名は利用者が設定します。Node.js版はローカルサブネット、Cloudflare版は共有する公開IPで一覧を分けます。

## セキュリティと制限

- 受信側の承認後に接続します。PINは確立した暗号化WebRTCチャネル内で照合し、PIN自体をシグナリングAPIへ送信しません。
- ファイル本体はシグナリングサーバーを通りません。接続確立には STUN を使うため、完全オフラインのネットワークでは繋がらないことがあります。
- カメラは不要です。HTTPS または localhost で開いてください（WebRTC の制約）。
